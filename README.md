## 摘要

在同一页面内反复翻页、抄录数字、人工加总，是这类页面的常见工作方式：
数值错了不会有人提示，格式每次都要手工统一。

本扩展在页面的原生导航里注入一个入口（样式与相邻项一致），点击后在面板内
按模板取数、成文、校验，一次完成。**出稿与否由使用者判断，程序不下结论。**

## 核心能力

| 能力 | 说明 |
|---|---|
| **多段默认正文** | 默认四段，标题、内容与段数均可改，最多 6 段 |
| **模板即正文** | 句号、填数位置、日期写法全部由模板定义；插入菜单统一一个入口 |
| **按需取数** | 模板未引用的数据源不发起请求；失败不放大，只重试一次 |
| **交叉校验** | 20 余项数据自洽与跨表校验（按数据条件触发），红 / 黄 / 绿三态，每条可展开查看判据与处置 |
| **时间基准可调** | 默认每日固定时刻结算、精确到秒；点面板顶部那一行即可改为任意时刻 |
| **同比自动计算** | 按去年同窗口实查；特定年份可走内置月度表，分母可溯源 |
| **复制 / 导出** | 纯文本或 txt 两种出口；校验未通过时两条出口均留痕 |
| **说明内置** | 面板内可查 51 条问答、23 项校验说明、5 条已知问题，按分类浏览或关键词检索 |
| **配置共享** | 所有安装本扩展的浏览器共用一份配置：改完自动上传、打开页面自动取回，无同步码 |
| **出错留痕** | 记录稳定短码、模块名与版本，减少口述成本 |

**默认四段正文。** 顺序为「当日 → 全量 → 年度累计」，累计段置于末尾。
以下为默认模板的段落构成，标题、内容与段数均可改；模板未引用的数据源不发起请求。

| 段 | 内容 |
|:--:|---|
| ① | 当日概览：总量 + 分类构成 |
| ② | 当日要情：按类别与区域拆分的明细 |
| ③ | 汇总段落：当日与去年同期对照 |
| ④ | 累计段落：年度累计 + 分类占比 + 处置类指标 |

## 安装与加载

> 前置条件：Chrome / Edge 111 及以上（Manifest V3）。

源码里有两个**构建期占位符**，`debug/dist.js` 生成成品时才会替换成真地址。
本仓库不含任何具体地址；使用者需要自己填。

| 占位符 | 含义 | 填在哪里 |
|---|---|---|
| `__SITE_ORIGIN__` | 目标站点根地址（`manifest.matches`、接口根、标签页判定） | `ops/host.json` 的 `site` 字段，或环境变量 `SITE_ORIGIN` |
| `__HT_ORIGIN__` | 分发源地址（版本清单、诊断上报、配置同步） | 同文件的 `origin` 字段，或环境变量 `HT_ORIGIN` |

`ops/` 不入库，新建即可：

```json
{ "site": "https://你的目标站点", "origin": "http://你的分发源:端口" }
```

两个都填任意合法地址即可让扩展加载；`origin` 不可达时，版本检查与配置同步静默失效，
取数与成文不受影响。**不填则 `host_permissions` 不是合法 URL，浏览器直接拒绝加载。**

1. 按上表新建 `ops/host.json`
2. `node debug/dist.js` —— 生成 `dist/` 成品目录（41 个运行文件）
3. 打开 `chrome://extensions`（Edge 为 `edge://extensions`），右上角开启**开发者模式**
4. 点「加载已解压的扩展程序」，选择 **`dist/` 目录**（能看到 `manifest.json` 的那一层）
5. 打开目标页面，导航条上出现入口（位于相邻菜单项左侧）
6. 建议固定到工具栏：点扩展栏的拼图图标 → 固定

**为什么加载 `dist/` 而不是项目根目录。**
浏览器拒绝加载含 `_` 前缀文件或目录的扩展（`_locales` / `_metadata` 除外），报错只给出文件名。
`dist/` 只含运行文件，是"能装进浏览器的那一份"。

**修改代码后。** 先 `node debug/dist.js`，再到扩展页点刷新。少跑这一步，浏览器中运行的仍是旧版：
面板不报错，只是数字不更新——扩展页显示的版本号是 `manifest.json` 的，`dist/` 里的却是旧的。

> **更换加载路径等同更换一个扩展。**
> 未打包扩展的 ID 由绝对路径算出，`chrome.storage` 中的设置不会随之迁移，需重填一次。
> 路径确定后不要再改动。

## 使用流程

```
打开页面  →  点击导航入口  →  点击标题栏刷新
                              ↓
                    查看校验是否全部通过  →  复制 / 导出
```

**入口不显示任何状态标记**：无红点、无角标、不变色、不弹气泡，与相邻菜单项属同一套视觉。
能否出稿看面板标题栏的状态提示（`已就绪` / `未到点`），取数进度与结果在底部状态栏
（`取数中` / `已生成`）。

**面板位置可拖动**：按住标题栏空白处拖到屏幕任意位置，松手自动贴边并对齐网格，位置记忆到下次打开；
设置页「复位位置」可恢复默认。

## 成文与校验口径

**时间基准。** 默认以每日固定时刻为界，只取最近一个已结算周期：
昨日该时刻 → 今日该时刻前一秒。右端取基准时间前一秒，两个周期才不重不漏。
未到点显示「未到点」，此时生成取上一整天。
点面板顶部那一行可改为任意时刻（年月日时分秒），正文中的时间表述随之变化；点「跟随每天」回到默认。

**同比。** 分母两个来源，**表优先**：

- 特定年份 → 取内置月度表的**补录前**数据。该年曾被事后补录，全年总数比当时报出去的高出一截；
  用补录后的数比今年会常年偏低。表可覆盖时不查远端。
- 其它年份 → 去年同一窗口实查（去年窗口 = 今年窗口整体前推一年），分母跟随基准时间。
- 两边均取不到时正文写「同比x」，程序不猜。

**取数口径。** 总量取明细条数（不取页面上的计数字段）；数值指标取明细求和；
「有效性过滤」由单一开关控制。同一段话内的指标必须同源——**不跨账相减**。

**校验分级。**

| 级别 | 判据 | 对出稿的影响 |
|---|---|---|
| 🔴 红 | 数据自身不平（分类之和 ≠ 总数、下级 > 上级） | 仍可出稿，导出留痕 |
| 🟡 黄 | 两套口径不一致（不同报表域的同一指标），属正常差异 | 正文照出 |
| 🟢 绿 | 通过 | — |

每条校验均可在面板浮层内查到：校验对象、差值在什么范围内属正常、应如何处置。

**结构校验先行。** 取数前先验结构（段落在不在、列数够不够），出稿前再验算术。
页面改版时取值只会变成 `undefined`，而兜底会把 `undefined` 变成 0，从而生成一份数字全错的文案。
因此结构对不上时直接报「数据源结构变了」，**不出稿**。

## 隐私与数据策略

「发什么、不发什么」在代码中写成判据，不只是文档声明。以下为两条互相独立的链路。

### 链路一：诊断上报（默认开启，界面不提供关闭）

只在出错与取数失败时上报一份现场；正常生成时不多发一个请求。
另有一条每日心跳，仅说明该设备当前在用的版本。

**发送范围（仅至自建服务器）**

- 版本号、构建日期、浏览器版本、操作系统、语言
- **匿名安装 ID**：安装时随机生成的 16 位，卸载即清除，仅用于归并同一台设备的记录；不是账号，也不是机器指纹
- 稳定短码（如 `NET-TIMEOUT`）、模块名（`panel` / `http`）、校验项名
- 本次生成的结构：几段、几个请求、几项未通过、总耗时

**不发送范围**

- 任何业务数值：总数、分类数、同比、损失
- 区域名、单位名、地址、模板正文
- 登录凭据、cookie、token、页面 URL

> 该边界由机器校验：自检脚本断言校验类事件的说明文字只允许小写字母与点号，写入数字即失败。

### 链路二：配置同步（默认开启，可在设置中关闭）

- 云端只有**一个槽位**，所有安装本扩展的浏览器共用：无同步码，也不需手动上传或取回。
- 上传的是**配置本身**：段落模板正文、区域名单、屏蔽规则、若干数值。不含业务数据、账号信息或页面内容。
- 修改配置后数秒自动上传；打开页面时查询一次（同机 60 秒内限一次），云端更晚则自动取回。
  两台都改过时**后改者生效**——一份共用配置，不存在分叉。
- 每次取回前保留本机上一份，设置页提供「还原」；关闭「自动同步」后不发起任何请求。

## 版本规范

遵循[语义化版本](https://semver.org/lang/zh-CN/)，格式为 `主版本.次版本.修订号`。
Git tag 与发布标题写作 `v1.10.7`，其中 `v` 仅为标签前缀，不属于版本号；
`manifest.json` 内始终为裸版本号 `1.10.7`。

规范要求「先定义公共 API」。本扩展的对外接口只有四项：

| 公共 API | 具体内容 |
|---|---|
| 模板占位符 | `{{f:day.C}}` 这类字段名：使用者已写在模板中 |
| 配置字段与默认值 | 时间基准、区域名单默认值等，改动会改变成文结果 |
| 存储结构 | `chrome.storage` 中档案的形状 |
| 成文口径 | 某句话取哪个数、分母是谁 |

据此确定版本位：

| 变动 | 递增位 | 示例 |
|---|---|---|
| 不兼容改动：老模板、老配置不能直接使用 | **主版本** +1，次版本与修订号归零 | 占位符改名、存储结构换形状 |
| 向下兼容的新功能 | **次版本** +1，修订号归零 | 新增一段可选正文、多一个开关 |
| 向下兼容的修正：缺陷、文案、样式、打包 | **修订号** +1 | 修一处取数、改一句措辞 |

两条硬约束：

- **已发布的版本不再改动内容。** 同一版本号永远对应同一串字节，因此打包时间戳固定、包内说明不写构建日期。
  改动内容即发布新版本号。
- **一个版本号只有一个来源。** `manifest.json` 与 `src/data/release.js` 的值必须相同。

## 本地开发与构建

```bash
node debug/build_font.js    # 重新裁界面字体子集（改了界面文案才需要跑；--dry 只报字数）
node debug/dist.js          # 生成 dist/ 成品目录（浏览器加载它；改完代码先跑这条再刷新）
node debug/pack.js          # 只打安装包，sha256 与发布版本一致
```

> 自检脚本、离线回归与发布脚本不随仓库分发，仅维护者本地保留。

**这个仓库只放产品本身。** 自检与回归脚本逐条写着具体取数口径（哪一段话取哪几个数、
哪些情形算矛盾），等于把业务规则抄一遍；使用说明与内部文档同理。它们留在维护者本地，
各自独立维护。所以这里没有 `npm test` 一类入口 —— 是这么分的，不是漏了。

`dist.js` 从 `manifest.json` 推导运行文件清单，逐项核对 `debug/files.js`，多余的一律删掉——
它产出的是"能装进浏览器的那一份"，不是"项目的一份拷贝"。

<details>
<summary><b>对接真实报文</b></summary>

这类平台**没有接口文档**。`src/data/contract.js` 中的地址、参数名、列下标、字段名，全部由真实响应反推——
每见一份新报文，就可能推翻一处旧结论。已确认的反例：`total: 0` 却返回 10 条列表、
可选字段时有时无、汇总是类型 1 还是 4。

逆推一律以报文为准。**一次出稿只导一次**，不逐条复制：

1. 开发者工具 → **网络** → 点清空 → 筛选框中输入接口前缀（只留接口，去掉图片与脚本）
2. 正常出一次稿，等待其完成
3. 导出。**部分浏览器的「复制为 HAR（已清理）」响应体为 0 字节，不可用**；
   有「全部另存为 HAR（含内容）」的用它，没有则退回逐条复制：
   右键某条请求 →「复制为 fetch」存为 `_har/X-请求.txt`；再「复制响应」存为 `_har/X-响应.json`
4. 存入 `_har/`，文件名带上查询条件
5. 按字段名整理成结构表（这一步的脚本与产物不随仓库分发）

`_har/` 已由 `.gitignore` 排除：HAR 内含 token 头与 cookie，推送即等于公开登录态。
整理后的字段结构（字段名、列下标，不含值）由维护者另行存档，不随仓库分发。
字段约定以 `src/data/contract.js` 为准。

## 项目架构

**依赖严格单向：`lib → data → domain → ui`。** 下层不感知上层存在；`domain` 内不出现 DOM，
`ui` 内不出现 `fetch`。清单中的脚本顺序与 `debug/files.js` 逐项一致。

```
manifest.json          扩展清单（资源白名单 + 脚本加载顺序）
background.js          Service Worker：工具栏入口；版本检查与上报的唯一请求出口
panel.css              面板样式（注入 Shadow Root）
options.html|css|js    设置页宿主，逻辑不在此处
src/lib/               公共层：util（数值 / 凑整 / 公文日期）、obs（事件缓冲，只收不发）
src/data/              数据层：errors（错误措辞）、contract（站点契约）、release（版本策略）、
                       config、window、http、faq、settings-schema、cloud、cas-last
src/domain/            领域层：render（占位符）、segments（整段成文）、phrases（成品句）、
                       checks（校验）、report（取数计划 → 事实 → 成文）
src/ui/                表现层：panel、settings、editor、faq、feedback、geom、dom、
                       nav（入口注入）、sections、checks、sitehider
```

**三处「唯一来源」不合并**：`errors.js`（错误措辞）、`contract.js`（站点契约）、`release.js`（版本策略）——
合并只会让「改一处就够」退化为「大文件里的某一节」。

## 已知限制

| 限制 | 原因 |
|---|---|
| 不能自动更新 | 浏览器在 Windows / macOS 上拒绝非商店扩展的 `update_url`，只能「发现新版本 + 覆盖文件 + 在扩展页点刷新」 |
| 只在一个站点上运行 | content script 的匹配范围由 `manifest.json` 声明，换站点要改清单 |
| 不接触登录凭据 | 复用页面登录态，不读 cookie、不存密码 |
| 占比合计强制 100.00% | 最大余数法分配，代价是某个小项可能比页面少 0.01%（主项永不参与削减） |
| 明细字段名不做美化 | 直接使用页面字段名，改名会让口径更难核 |
